SQL Injection: Authentication Bypass

Compare an unsafe login query with the same login protected by parameterized SQL.

Vulnerable mode: input is inserted directly into the SQL query.

Query used by the backend


      

    


    

      
Vulnerable query pattern

      
SELECT ... WHERE username = '${username}' AND password = '${password}'

      
The application joins user input into the SQL text. A crafted username can change the query's meaning and comment out the password condition.

      

      
What to remember

      
    
        
  • Root cause: SQL syntax and user input are combined in one string.
    • 
        
  • Fix shown here: parameterized query using ? placeholders.
    • 
        
  • Other defenses: allow-list validation, least-privilege database permissions, and generic error messages.
